# 发布后数据复盘（post-publish-review）

## 一、看什么（指标与含义）

| 指标 | 看什么 | 诊断 |
|---|---|---|
| 播放量 | 总量+趋势（是否持续上涨） | 低=选题/封面/前3秒问题 |
| 完播率 | 观众看到哪 | 前段流失=钩子弱；中段流失=节奏/反转弱；尾段流失=结尾弱 |
| 互动率 | 点赞/评论/转发/收藏 | 低=情绪共鸣弱；评论多=话题性强 |
| 涨粉 | 转粉率 | 内容有没有"非看不可"的价值 |
| 观众评论 | 高赞评论/负面反馈 | 需求证据+改进方向（免费调研） |

## 二、复盘流程（发布后 3-7 天做）

1. **拉数据**：平台后台播放/完播/互动/评论（比赛场景：数据截止前核对播放量，预估能否进档）；
2. **定位流失段**：完播曲线对照分镜表——哪一镜观众开始走？那一镜的钩子/反转/情绪有没有立住；
3. **对照选题验证**：当初 topic-validation 的评分 vs 实际数据——市场判断准不准（校准选题方法）；
4. **提炼需求证据**：评论区高赞/喊话 = 下一部的选题素材（存进 topic-validation 证据库）；
5. **输出迭代报告**（≤1 页）：

```markdown
## 复盘报告：{作品}
- 数据：播放/完播/互动/涨粉（对标同类）
- 流失段：{镜号/时间段}，原因：…
- 选题验证校准：预测 vs 实际，偏差：…
- 下一部改进项（按优先级）：
  1. 钩子：…
  2. 节奏/反转：…
  3. 题材/切口：…
- 观众需求证据（评论高赞）：…
```

## 三、比赛场景专用

- 数据截止前每天核对播放量（参赛评分占 60%）；
- 播放量不达标时评估：邀请好友/多账号分发/话题运营（合规范围内）还是转投其他比赛；
- 获奖核验前留存完整工作流证据。

## 四、门禁

- 有真实后台数据（不靠感觉）；
- 流失段定位到具体镜/时间段；
- 迭代项 ≥3 条且可执行（不是"做得更好"这种空话）；
- 需求证据来自真实评论（可溯源）。

## 五、与总控衔接

挂在 `video-command-center` 十环之后（闭环）：发布（publish-automation）→ 本技能复盘 → 迭代项回流 topic-validation/storytelling（下一部）。比赛场景在数据截止前按日复核播放量。

## 六、强化升级（蒸馏自开源 retention 方法论，详见 `references/post-publish-review-open-source.md`）

1. **锐降优先于缓坡**（TubeAnalytics）：30 秒内下降 >10 个百分点=具体问题时刻，先治锐降（钩子/转场/反转），缓坡是正常流失；
2. **掉落模式映射表**（OpusClip）：跨作品累积 `标题|时间戳|当时画面在发生什么`，≥5 部后找重复模式（总是 intro 走人/总在转场掉→按模式改结构）；
3. **一次只测一个变量**（TubeAnalytics 铁律）：每部只改 1 个结构变量（钩子/节奏/结尾三选一），对比新曲线 vs 频道基线→保留或回退→沉淀 evidence-based 模板；
4. **intro 基准**（YouTube 官方）：30 秒后 ≥50% 观众=above typical，低于则优先改前 30 秒；
5. **迭代项可执行化**（Subscribr）：每项落到具体动作（写更紧的 intro/掉落处加 B-roll/换缩略图），不写"做得更好"式空话。
