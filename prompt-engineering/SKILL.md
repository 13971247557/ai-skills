# 全领域提示词工程手册（prompt-engineering）

## 一句话用途

你在给「副导演/配音导演/编曲师/剪辑师」提要求，不是给神许愿——本手册把抽象想法翻译成**各平台能稳定执行、可直接复制的提示词**，并告诉你每条为什么有效、怎么写不会翻车。

**什么时候读本手册**：任何 AI 生成任务（生图 / 生视频 / 配音 / 音乐 / 音效 / 字幕 / 剪辑）需要从零写提示词，或出图出片翻车要找原因时，先读本手册对应领域文件。

## 快速上手（四步）

1. **定层 + 选模板**：先读 `references/master-prompt.md` 第一节决策分支——判断你在三层中的哪一层（喂生图出首帧=第一层长提示词 / 排整片分镜=第二层元提示词 / 喂图生视频=第三层短公式）；再去 `references/templates.md` 找最接近你场景的模板，复制骨架。
2. **按情境微调**：替换【变量】；按 `references/general-principles.md` 检查是否符合通用法则；按领域文件补公式词库。
3. **对照反例自查**：写完后翻对应领域文件的「反例/翻车点」清单逐条排除。
4. **识别验证门禁（强制，调用生成工具前必过，双层）**：
   - **第 1 层·规则门禁（确定性，零 LLM 消耗）**：跑 `scripts/prompt_check.py --prompt "…" [--anchor "锚点句"] [--intent "用户原始需求"] [--script-args "…"]`——检查否定词陷阱/抽象词/模糊方位/占位符/引号纪律/领域必填要素/**一致性锚点逐字包含**/**意图核心词覆盖**/脚本参数合法性；**退出码 0 才进入第 2 层**，FAIL 修正重跑。
   - **第 2 层·语义识别验证（AI 执行，轻量一次过，像人一样思考）**：对提示词做「三查六问」，理解生成逻辑，不只看字面：
     - **① 意图对齐**：提示词是否忠实表达用户最开始的想法——核心对象/动作/情绪/风格有没有被改写跑偏或丢失？换成"用户会认得出这是他想要的吗"来判断。
     - **② 叙事逻辑（为什么发生 / 怎么发生 / 谁跟谁）**：这件事**为什么**会发生（动机因果成立吗，如"深夜门外有人递信"不合理）；**怎么**发生（动作流程/时序/物理逻辑顺吗，如"先听到动静再起身看门"）；**谁跟谁**（角色关系清楚吗，谁对谁做什么，如"母亲→看信"而不是"信自己飞进家门"）。逻辑不自洽的提示词，画面必翻车。
     - **③ 生成逻辑反推（模型会怎么生成）**：站在模型视角想——这个提示词会被理解成什么画面？正脸老年女性会默认笑吗？否定词会不会触发联想？物体位置会不会漂移？与母版锚点对得上吗？场景符合故事线的时间/地点/意象吗？
   - **输出极简（省 token）**：每镜只给 `PASS → 生成` 或 `FAIL → 原因一行 + 改法一句`；不写长篇分析，不重复已通过的检查项。
   - 语义层与规则层**任何一层不过都不允许调用生成工具**。

> 核心心智模型：**图管「长什么样」，字管「怎么动/怎么演」**；i2v 里参考图已承载画面，提示词只写「怎么动」；纯文生时文字才从零搭画面。

## 多智能体联动校正（生成前互审互校，大片级定稿门禁）

**默认不启用（省 token 纪律）**：常规出片只走「快速上手」的双层门禁——第 1 层规则门禁 `prompt_check.py`（确定性脚本，**零 LLM 消耗**）+ 第 2 层轻量语义自检（一次过、输出极简）。本 9 角色互审（Writer+5 Reviewer+Chairman+Editor+Gatekeeper，需模拟多角色对话、token 消耗大）**仅在以下情况按需调用**：
1. 用户明确要求「大片级/多智能体校正/互审」；
2. 双层门禁仍不放行、且需要诊断性评审意见时。
完整流程见 `references/prompt-review.md`。

**六步闭环**：① Writer 按槽位模板写 v1 → ② **5 个评审角色并行**评 v1（镜头语言 / 光效氛围 / 一致性 / 节奏运动 / 可行性，各出 JSON 分数+must_fix）→ ③ Chairman 聚合去重、按 must_fix→should_fix 排序 → ④ Editor 按清单**一次只改一个维度**出 v2 → ⑤ Gatekeeper 对 v1/v2 **成对比较、交换顺序评两次**定放行 → ⑥ 定稿送生成。

**九条角色**：Writer + 5 Reviewer（镜头/光效/一致/节奏/可行）+ Chairman（聚合）+ Editor（修订）+ Gatekeeper（门禁）。

**门禁标准（量化）**：
- **硬性门禁（任一不过即不放行）**：一致性 overall ≥ 3/5；可行性 contradiction_check = 5/5；可行性 capability_boundary ≥ 3/5；**v2 不得在硬性维度（一致性/可行性）上输给 v1**。
- **软性门禁**：5 评审平均分 **≥4.0 直接放行 / 3.5–4.0 修一轮 must_fix 放行 / <3.5 修两轮仍不达则人工介入**。
- **循环上限 K=2**：最多修 2 轮；v2 不优于 v1 且达上限 → 取 v1 定稿，不无限打磨。

**PoLL 原则（硬纪律）**：评审模型必须与生成模型**不同家族**——否则模型有"自偏好偏差"（倾向给自己同族写的高分）。当前链路靠同一 LLM 分角色串行扮演近似执行；真·跨家族并行调度、JSON 自动解析门禁、资产文字锚点比对属**待新增**（详见 prompt-review.md 第七节）。

## 通用原则摘要（详见 general-principles.md）

- **正向优先**：写「要什么」（empty room），别写「不要什么」（no people）——否定词会先激活再抑制，残留率反升。
- **结构化分段**：模型对分栏/换行/标签有解析器，杂乱长段=注意力分散。
- **一个提示一个主任务/主情绪**：多目标互相打架，资源被分摊。
- **具体 > 抽象**：「高级感」模型不懂，懂 85mm f/1.8、68 BPM、35mm 胶片这种物理参数。
- **一致性=不变量逐字复制**：角色/光线/风格描述整段粘进每个镜头，只改变量，配固定 seed。
- **长度密度控制**：信息超预算模型就丢三落四（乐器≤4、负面词每组~5 个、一镜一动作）。
