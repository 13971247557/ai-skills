# ai-craft-methodology

> 用途：让每一次执行更聪明、一次到位——写提示词、生成图像、排错、反思改进时调用。
> 来源：OpenAI 官方 Prompt Engineering（6 策略）+ GPT-4o/DALL·E 图像一致性实测社区（Dre Dyson/aiqnahub/oreateai）+ Agent 推理方法论（CoT/Reflexion/MASS，arXiv 2504.18875 / 2510.09244）。

## 一、OpenAI 提示词工程 6 策略（写任何 prompt 前过一遍）

1. **写清晰指令**：细节越足输出越好；角色 persona（"你是资深档案员/电影摄影师"）。
2. **分隔符分块**：用 `###` / `"""` 区分指令、上下文、参考清单，别混成一坨。
3. **分步骤指定**：把任务拆成显式步骤（先锁场景→再改动作→再校光色）。
4. **给示例（few-shot）**：比抽象描述有效（如给一张"对的柜门打开"照片）。
5. **指定输出长度/格式**：明确要什么形态。
6. **正向陈述**："不要说不要什么，说该做什么"——`两扇门每扇都清晰可见：左门打开贴柜体左、右门关闭合拢` 优于 `任何一扇门都不得消失`。负向词（不得/禁止/不要）放最后收尾，主体用正向。

## 二、图像生成一致性控制（防漂移/防死锁）

1. **风格 token 锁定**：同一系列每张图的光照词/媒介词/纹理词必须逐字相同（`冷白荧光灯+窗外清冷晨光一束斜光+锈迹胶片颗粒` 全系列一字不差）。
2. **编辑优于重新生成**：改图用 image_edit 而非重画（保连续性）——但见第 3 条。
3. **会话污染（Session Contamination）＝漂移头号根因**：同会话连续生成会携带视觉上下文污染后续输出（style lock bug / 数据退化）。**独立关键帧尽量独立上下文/最小化连续派生**；连续派生 ≤2 代就必须回权威底图，禁止 5 代以上自叠代（本剧 v5→v11 柜门反复漂就是污染累积）。
4. **照片锁结构**：AI 对特定几何死锁（柜门打开/门板数）时，直接用真实照片当唯一底图，AI 只"化妆"（改质感/道具/光色），不重画结构。
5. **光照细节词**：具体光照术语（`冷白荧光灯管照明/清冷晨光斜射/顶光`）；明暗元素并存时暗部常胜出，注意平衡。
6. **单点编辑**：只坏一处就遮罩/局部改那一处，别整图重生。

## 三、Agent 智能方法论（自我提升循环）

1. **CoT 思维链**：复杂任务先显式推理再动手（场景逻辑→结构→光→细节清单→风险预判），推理外显比直接跳结论准。
2. **Reflexion 反思**：每次失败后回顾轨迹，写"哪里错了+下次怎么改"，沉淀进经验库作为下次短期记忆——**失败不是终点，是训练数据**。
3. **MASS 三角色自评**：产出自评=执行者（做了）→评估者（挑刺：对照分镜/权威底图逐项核）→优化者（改哪、怎么改）。交付前必须过一遍三角色。
4. **Planning 分层**：CoT 是基线；单一链路不可靠时探索多路径（ToT 树搜索）；需并行综合时合并分支（GoT）。

## 四、本剧（《她的名字》）落地锚点

- 柜门打开帧：照片锁结构（v13 已验证）；连续派生限 2 代内回 v30 权威。
- 光色/衣袖漂移：会话污染高发——每次生成都显式带完整风格 token 块（冷白荧光灯+清冷晨光+深蓝工装袖），不靠"保持上一版"。
- 每轮失败：先反思（哪错/根因/下次改法）→蒸馏经验→再动手，禁止同提示词换词重试。
