# 火山方舟 API 自动出片执行器

## 最高原则：出片质量第一位（用户硬要求，压过一切其他考量）

**质量 > 成本 > 速度。** 素材生成环节同样执行：
- 生成的视频/画面**不合格就重生成或换渠道**（水印、崩坏、画质差、人物不一致），不为省钱保留低质素材；
- 免费渠道（清影等）优先，但质量不达标时允许使用付费/高成本方案（去水印、更稳渠道），以"质量达标下的最低成本"为准；
- 成本确认仍先报价，但**不因省钱而接受低于质量线的产物**。

## 执行模式（用户硬要求）

**用户给专业提示词 → 本技能原样生成、完全符合，不自由发挥。**

- 用户每次生成时提供的提示词**原样采用**（不增删、不改写、不按爆款方法论"优化"）；
- 缺失生成必需参数（时长/比例）时仅补默认值并**在交付中标注**；用户已明确的参数逐项映射执行；
- 生成失败先原样重试 1 次，仍失败如实报告，不擅自改词；
- 创作方法论（ai-short-video）只在用户**明确要求**时使用。
- 完整规则见 `references/qingying-automation.md`「忠实提示词执行规则」。

## 生成前审核关卡（用户硬要求：先看素材图，再出视频）

**任何 AI 视频生成前，必须先出素材图给用户审核，确认后才生成视频。**

1. **先生成素材图**：用豆包系画图能力（豆包网页/App 画图、即梦、小云雀 Seedream 等）按用户提示词生成**角色设定图 / 场景设定图**（质量优先，无水印/高清晰）；
2. **给用户看**：素材图通过图片卡片交付给用户，让用户判断是否符合想象；
3. **用户确认才继续**：用户确认后，才用该图作**参考图**走**图生视频**（清影「图生」模式或方舟图生视频），保证人物/场景跨镜头一致性；
4. **否图就迭代**：用户不满意 → 按反馈修改提示词重新出图，直到确认，**绝不跳过审核直接生成视频**；
5. **审核关卡在成片链中的位置**：用户提示词 → 素材图 → 用户确认 → 图生视频（分镜逐镜）→ 配音/字幕/合成成片。

## 跨镜头主体一致性（用户硬要求：讲故事的前提，零差错）

**多镜头合成成片时，主体（角色/场景/关键物件）跨镜头必须完全一致，这是故事连贯的底线。**

1. **一致性锚点**：每个核心角色/场景一张经用户确认的**设定图**，全片所有镜头都以它为唯一参考——这是全流程最关键的资产；
2. **参考图锁定**：同一角色/场景的所有镜头**必须用同一张设定图**做图生视频参考，禁止中途换图、禁止跨镜头重开新形象；
3. **提示词锚定**：同一主体的提示词使用**同一身份描述模板**（固定外貌/服装/特征词），跨镜头只改动作/镜头/场景，不改主体描述；
4. **逐镜核验**：每个镜头生成后对照设定图核验——形象、服装、发型、色调、场景物件是否一致；不一致**立即用同一参考图重抽**，不把残差带到成片；
5. **成片终检**：成片合成前逐镜检查（见 `video-edit-pipeline/references/quality.md` 一致性项），任一镜不一致即重做该镜。

## 大片级生成执行规范（2026-10 生成域精研落地，出电影感必守）

> 完整 SOP、ffmpeg 命令与能力边界见 `references/film-grade-generation.md`；提示词措辞见 `prompt-engineering` 的 video.md 第十一章 / templates.md 第四章。

- **真长镜拆成 4–6 秒节拍**：>6–8 秒主体漂移/脸融/背景塌概率显著上升；不要赌一个超长镜头，拆段在剪辑里伪装连续。
- **尾帧→首帧链式交接**：一段批准后用 ffmpeg 抽它最后一帧，托管成 URL 当下一段 `--ref`。⚠️ 本脚本 `video` 子命令**只暴露 `--ref` 首帧、无尾帧参数**（已核对 argparse），首尾帧双锚 `end_image_url` 属待新增手段。
- **相邻段四连续**：动作重叠 6–12 帧交叉淡化（ffmpeg `xfade`）、相同运镜词、相同镜头方向、相同色温；切点藏在转身/过门/甩摇中间；链满 3 段插一次超分（超分需外部工具 Topaz/DaVinci，本链路未内置）。
- **固定镜头显式写 `no camera movement`**：否则模型自己缓慢漂/变焦；配 `no slow zoom, no camera drift, no random pan`（prompt-only 引擎写进句尾）。
- **小房间不写 crane / 大全景 / 360° 环绕**：空间装不下会几何扭曲；室内用 dolly/tracking，开阔地才用 crane/orbit；一次最多 2 个同时运动。
- **先低档 5s 小样验路径**：`--model doubao-seedance-2-0-mini-260615 --duration 5 --resolution 720p` 确认运镜路径/构图/色温对了，再同一提示词换旗舰档正式出片（质量第一位，不因省钱保低质）。

## 概述

用 `scripts/ark_pipeline.py`（python3 标准库，无第三方依赖）直接调用用户自己的火山方舟 API，把文案、角色设定图、镜头视频自动生成到本地。**与 `ai-short-video` 技能配合**：`ai-short-video` 负责选题/文案/分镜/发布（创作侧），本技能负责执行生成（生产侧）。

## 命令速查

| 环节 | 命令 |
|---|---|
| 文案/分镜 | `python3 scripts/ark_pipeline.py text --prompt "…" --out 剧本.md` |
| 文生图 | `python3 scripts/ark_pipeline.py image --prompt "角色设定图…" --size 1024x1024 --out 素材/` |
| 图生视频 | `python3 scripts/ark_pipeline.py video --prompt "分镜提示词…" --ref <设定图URL> --duration 5 --ratio 9:16 --out 素材/` |
| 文生视频 | `python3 scripts/ark_pipeline.py video --prompt "…" --duration 5 --ratio 9:16 --out 素材/` |
| 列模型 | `python3 scripts/ark_pipeline.py models` |

`--model` 可传模型 ID（如 `doubao-seedream-5-0-flash-260915`）或**推理接入点 ID（ep-xxxxx）**。`--config` 指定含 Key 的 json；Key 读取顺序：环境变量 `ARK_API_KEY` → `--config` → `./data/config.json` / `video-studio-web/data/config.json`。Key 只读、不写日志、绝不回显。

## 额度与激励策略（省钱模式，强制）

用户额度有限、成本敏感时**必须先报预估费用、用户确认后才调用**；文案环节始终免费可继续。

| 环节 | 模型 | 免费/激励 | 调用方式 |
|---|---|---|---|
| 文案 | `doubao-seed-evolving` | ✅ 每个模型 50 万 token 免费额度；✅ **协作奖励计划：首次授权立得冷启动包，每日调用≤50 万 tokens（个人），次日 1 点后返还等量资源包（30 天有效）** | 参与计划后 `--model` 填授权接入点 ID（ep-xxx）才计返还 |
| 文生图 | `doubao-seedream-5-0-flash-260915`（便宜）/ `-pro-260628`（精品） | ❌ 视觉模型**无免费额度**，按张计费 0.20~0.30 元 | 生成前报价确认 |
| 视频 | `doubao-seedance-2-0-mini-260615`（最省，促销 4 折约 0.2 元/秒）/ `-2-5-260628`（旗舰） | ❌ 无免费额度；⚠️ **开通门槛：账户余额≥200 元或购买 Seedance 资源包**；未满足前**禁止调用，降级手动**（即梦/可灵/体验中心） | 满足后仍须先报价确认 |

**协作奖励计划要点**（详见 `references/ark-api.md`）：
- 参与：控制台「开通管理」→ 协作奖励计划活动页 → 授权模型 → 为该模型创建推理接入点。
- 返还：**通过授权接入点调用**的用量，按模型维度次日返还等量免费资源包；未走授权接入点不采集、不返还。
- 个人上限每日 50 万 tokens/模型；企业认证后最高 500 万。
- 当前计划内重点模型：`doubao-seed-evolving`（文案）；Seedream 5.0-Lite/4.5/4.0 与 Seedance 1.x 已于 2026-09-01 退出，Seedream 5.0-Pro 等 9 款 2026-10-08 退出——**图像/视频新模型（Seedance 2.x、Seedream 5.0-flash）不在计划内，无次日返还**，按量付费。
- 数据授权：参与即授权调用数据用于模型优化（匿名化加密），可随时撤回。

## 错误码速查

| 错误码 | 含义 | 处理 |
|---|---|---|
| `ModelNotOpen` | 模型未开通 | 控制台开通；视频需先满足余额≥200 元/资源包门槛 |
| `InvalidEndpointOrModel.NotFound` | 模型已下线/无权/ID 少了版本后缀 | 用 `models` 命令查完整 ID |
| `InvalidParameter` | 参数不支持 | 查模型规格（时长/比例/分辨率） |
| 余额/限流类 | 额度不足/频率限制 | 换低档模型、降并发、稍后重试 |
| 任务 `failed` | 生成失败/审核拒绝 | 重写提示词，不反复硬撞 |

## 生产流程（配合 ai-short-video 阶段 3–6）

1. 文案/分镜：`text`（免费额度 + 协作奖励返还）。
2. 角色/场景设定图：`image` 先出（生成前报价）。
3. 镜头视频：`video --ref 设定图URL`（图生视频保一致性；先 mini 草稿验证，后旗舰成片）。
4. 废片在生成端拦截：一致性/口型/手部不合格的镜头，固定参考图重抽；**清影裁切后必跑 `ffprobe -v error -select_streams v:0 -show_entries stream=width,height -of csv=p=0 <file>` 核对分辨率**，出现 720×720 或与预期比例不符（React 弹窗点击不稳/参数未生效）→ 视为裁切失败，`bu.snapshot()` 看弹窗状态后重裁或重生成，错误分辨率禁止进成片（详见 `references/qingying-automation.md`「裁切后强制分辨率质检」）。
5. 配音：账号无方舟 TTS 时用剪映/豆包配音；字幕 SRT 由剧本生成；最后剪映/ffmpeg 合成。
